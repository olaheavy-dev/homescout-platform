# 0025: AI platform capabilities

**ID:** AI-05 (accepted), AI-03 and OP-01 (in part)  
**Status:** Accepted  
**Date:** 2026-10-23  
**Stage:** 6 (requirements decided early)

## Context
The founder wants HomeScout's AI layer (decision 0023, Microsoft Agent Framework) to cover the full breadth of production practice, built **according to the official documentation**, and debuggable locally with Aspire, as a comprehensive learning experience.

## Options
- **Minimal AI layer, add capabilities when needed:** less work, less learning, and gaps appear in production.
- **Full capability set designed in from the start (chosen):** each capability is a planned, documented building block.

## Recommendation
The full set, built in the order below, each one evaluation-first.

## Decision
The AI layer must include these capabilities. Each implementation pull request links the official documentation section it follows; any deviation needs a decision record.

| Capability | What it means for HomeScout | How (official approach) | Official documentation |
|---|---|---|---|
| **Evaluation first** | Before building any AI task, write its evaluation set (questions, reviewed answers, cited pages, attack cases) and its pass threshold. The task is done when it passes; prompt or model changes that lower scores don't merge | Agent Framework evaluation and `Microsoft.Extensions.AI` evaluation libraries | [Agent evaluation](https://learn.microsoft.com/en-us/agent-framework/agents/evaluation), [evaluation libraries](https://learn.microsoft.com/en-us/dotnet/ai/evaluation/libraries) |
| **Tracing with OpenTelemetry** | Every agent run, model call, tool call and workflow step is a trace span, following the OpenTelemetry generative-AI conventions | Agent Framework observability; `UseOpenTelemetry` on chat clients | [Agent observability](https://learn.microsoft.com/en-us/agent-framework/agents/observability), [workflow observability](https://learn.microsoft.com/en-us/agent-framework/workflows/observability), [GenAI semantic conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/), [OpenTelemetry for .NET](https://opentelemetry.io/docs/languages/dotnet/) |
| **Local debugging with Aspire** | One command starts the API, database and dependencies locally; the Aspire dashboard shows traces, metrics and logs, including agent and model calls | Aspire app host and dashboard | [What is Aspire](https://aspire.dev/get-started/what-is-aspire/), [Aspire dashboard](https://aspire.dev/dashboard/overview/), [standalone dashboard](https://learn.microsoft.com/en-us/dotnet/aspire/fundamentals/dashboard/standalone) |
| **Token and cost monitoring** | Input and output tokens recorded per task, agent and model; cost computed in plain code from a versioned price table; the daily model-spend cap (doc 04 §6) is enforced and alerts fire before it's reached | OpenTelemetry token-usage metrics from the GenAI conventions | [GenAI semantic conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/), [.NET observability with OpenTelemetry](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/observability-with-otel) |
| **Prompt injection defence** | Uploaded documents and replies are treated as quoted data, never instructions; tools are denied unless allow-listed; document content can never trigger an action; attack cases are in every evaluation set | Agent Framework middleware and guardrails; tool approval; optional injection detection (candidate: Azure AI Content Safety Prompt Shields, subject to cost-first rule 0022) | [Agent safety](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/safety), [middleware](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/middleware/), [termination and guardrails](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/middleware/termination), [Prompt Shields](https://learn.microsoft.com/en-us/azure/ai-services/content-safety/concepts/jailbreak-detection), [OWASP Top 10 for LLM applications](https://genai.owasp.org/llm-top-10/) |
| **Output filtering and content safety** | Answers use structured output; middleware checks every claim cites a figure ID or document page, every number matches a supplied figure, and content is safe; personal data is redacted before text is sent to a model; failures return "not known" or "refused" | Structured outputs, result-override middleware, content safety filter (provider built-in or Azure AI Content Safety, cost-first) | [Structured outputs](https://learn.microsoft.com/en-us/agent-framework/agents/structured-outputs), [middleware](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/middleware/), [Azure AI Content Safety](https://learn.microsoft.com/en-us/azure/ai-services/content-safety/overview) |
| **Workflows** | Document investigation runs as a graph workflow with explicit steps and saved progress, so it can pause and resume | Agent Framework graph workflows, checkpoints | [Workflows overview](https://learn.microsoft.com/en-us/agent-framework/workflows/), [edges](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/edges), [checkpoints](https://learn.microsoft.com/en-us/agent-framework/workflows/checkpoints) |
| **Human-in-the-loop approval** | The workflow pauses for the user to approve drafted questions; any tool with side effects needs approval | Workflow human-in-the-loop requests; tool approval | [Human-in-the-loop](https://learn.microsoft.com/en-us/agent-framework/workflows/human-in-the-loop), [tool approval](https://learn.microsoft.com/en-us/agent-framework/agents/tools/tool-approval) |
| **Conditional routing and agent router** | Route to the right task by plain code where the screen already knows the task; use a routing step only for open chat questions; route to a cheaper model first and a stronger one only when needed | Workflow conditional edges and handoff; runtime model routing | [Edges](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/edges), [handoff](https://learn.microsoft.com/en-us/agent-framework/workflows/orchestrations/handoff), [runtime model routing](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/runtime-model-routing) |
| **Semantic caching** | Reuse answers to repeated, non-personal questions (for example "what does leasehold mean") to save cost. Exact-match caching first; similarity matching only where an evaluation shows it returns correct answers. **Never cache across users or anything based on a user's own documents.** Cache keys include the prompt and evidence versions | No ready-made semantic cache was found in the Agent Framework docs; built from documented parts: embeddings and a vector store (pgvector, decision AI-02) | [Vector stores in .NET](https://learn.microsoft.com/en-us/dotnet/ai/vector-stores/overview), [Microsoft.Extensions.AI](https://learn.microsoft.com/en-us/dotnet/ai/microsoft-extensions-ai) |
| **Streaming answers** | Answers appear as they're generated. Where a guard needs the whole answer (citation and number checks), the screen streams progress and shows the checked answer | Agent Framework streaming runs | [Running agents](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/running-agents) |

## Consequences
- **Build order at stage 6:** evaluation harness → tracing and Aspire → token and cost monitoring → one task agent with output guards and injection defence → streaming → chat panel → workflow with human approval → routing → caching last, once usage shows repeated questions.
- **AI-05 (AI safety)** is accepted as these requirements. **AI-03 (evaluation)** is accepted in part: evaluation first, tooling pinned at stage 6. **OP-01 (observability)** is accepted in part: OpenTelemetry everywhere and Aspire for local debugging; where production telemetry goes is decided at stage 6, cost first.
- Paid safety services are candidates only; the cost-first rule (0022) applies.
- New packages (Aspire, OpenTelemetry, safety services) are added at stage 6, each a founder merge as a new dependency (0024), and listed in `docs/references/third-party.md`.
